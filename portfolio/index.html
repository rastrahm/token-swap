// 01 — CONTEXTO

Por qué este proyecto

Dentro de mi suite EVM, el módulo 06 reconstruye un AMM estilo Uniswap V2 desde cero: Pair, Factory y Router con Foundry. No es un fork: es material de referencia con K-check, gas y auditoría SWC — las capas que más me importan en DeFi on-chain.

// 02 — TRES PILARES

Qué entrega el módulo

// PILAR_01

AMM x · y = k

TokenSwapPair, Factory y Router: swaps con fee 0.3%, mint/burn de LP (Math.sqrt) y acumuladores TWAP en _update().

  • K-check post-swap (997/1000)
  • Slippage + deadline en Router
  • Custom errors · CEI · nonReentrant
// PILAR_02

Optimización de gas

SafeTransfer propio, immutables, reservas uint112 empaquetadas, ReentrancyGuard EIP-1153 y unchecked acotado.

  • Snapshot e2e en test/gas/
  • Cache token0_/token1_ en hot path
  • Tradeoffs documentados en GAS-ES.md
// PILAR_03

Verificación de ataques

Matriz SWC-100–136, fuzz ≥ 1000, invariantes k y suite de reentrancy (SWC-107) donde el ataque debe fallar.

  • 33 mitigados · 3 informativos · 0 vulnerables
  • 60 tests verdes (unit/fuzz/invariant/attack/gas)
  • UI Next.js: swap + liquidez + tema
// 03 — OPTIMIZACIÓN DE GAS

Hot path barato, tradeoffs claros

Fase 8: baseline en doc/GAS-ES.md y .gas-snapshot. El foco es lecturas baratas en mint/swap/burn, bubble-revert en transfers y guard EIP-1153 — no micro-ahorros ciegos.

Optimización Tradeoff / efecto
SafeTransfer (low-level call + bubble-revert) SWC-104; propaga ReentrancyGuard; ligero ↑ deploy vs OZ SafeERC20
immutable factory / token0 / token1 Lecturas baratas en cada operación del Pair y Router
Reservas uint112 + uint32 empaquetadas 1 slot menos vs dos uint256; patrón Uniswap V2
ReentrancyGuard EIP-1153 (tstore) Sin SSTORE permanente en el guard de mint/swap/burn
unchecked aritmética acotada + cache token0_/token1_ Menos overhead post-checks; menos lecturas immutable repetidas
skim condicional + constante _K_DENOMINATOR Omite transfer si no hay excedente; evita recalcular 1000²
Custom errors + path Router fijo (2 tokens) Reverts compactos; gas e2e predecible sin loops multi-hop

// 06 — CAMPAÑAS DE ATAQUE

Defensivo, no ofensivo

Suites Foundry donde el “ataque” solo cuenta si revierte. Sin PoCs de exploit: reentrancy en mint/swap/burn, slippage, invariante k y superficie vacía (sin ETH / selfdestruct).

A

Reentrancy

SWC-107: reenter mint/swap/burn durante callback de token.

B

K / fee

Fuzz e invariante: k no baja tras swap con fee 0.3%.

C

Slippage

Router revierte si amountOut < amountOutMin.

D

SafeTransfer

Transfer fallida o false → revert completa (SWC-104).

E

N/A

Sin ETH, selfdestruct, delegatecall ni flash swaps.
